# 双语变更条目

后续完成功能、修复或值得向用户说明的文档／发布流程变更时，在同一次改动中向 `entries/` 添加简短双语条目。Release 工作流自动按上一已发布版本汇总，无需另行手写 Releases 页面。

文件名使用小写字母、数字和连字符，例如 `20261015-release-automation.json`。每项中文与英文一一对应，说明用户可观察到的变化；不要把未实现计划写成已交付功能。

```json
{
  "schemaVersion": 1,
  "changes": [
    {
      "zh": "修复某个具体操作中的问题，并说明修复后的行为。",
      "en": "Fixed the issue in a specific operation and describe the resulting behavior."
    }
  ]
}
```

- 每个文件 1～20 项，每项 zh／en 都是非空单行文本，不包含外层列表符号或标题；单项最多 2,000 字符。
- 多次提交属于同一个未发布功能时，可以修改尚未发布的条目，避免重复。发布后不修改、移动或删除旧条目；纠正说明时添加新文件。
- 条目永久保留。工作流从上一个已发布标签读取旧文件列表，只汇总新文件，按文件名排序；已发布文件发生修改或删除会拒绝发布。
- 不需要版本专属的说明文件，也不在发布时自动提交、删除条目或修改版本。
- 纯内部且不影响使用或维护的改动可不加条目；正式发布仍必须至少有一条未发布双语变化。
- 固定格式为“更新内容”中文列表、“Changes”英文列表和兼容说明。宿主基线或价格行为改变时，同步更新 `scripts/release-notes.mjs` 的兼容说明及项目文档。

本地预览（将基线替换为上一次实际发布的标签）：

```sh
npm run release:notes -- --from v0.1.4
```

输出为 `work/release/notes.md`，不会创建标签、发布或改动远程仓库。正式发布与试运行见 [发布指南](../docs/releasing.md)。
